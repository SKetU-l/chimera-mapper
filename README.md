# chimera-mapper

Configuration tool and side-button mapper for the **Kreo Chimera V1** mouse.

Set DPI, polling rate and lighting, remap every button and upload macros
straight to the mouse's memory, from Linux or macOS, without Kreo's
Windows-only software. Settings stored on the mouse keep working on any
computer, with nothing running in the background.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/SKetU-l/chimera-mapper/main/scripts/install.sh | bash
```

Run it as your normal user (it asks for `sudo` when it needs it). The installer will:
- Install build dependencies if missing (a C compiler, `pkg-config`, libudev headers) and Rust
- Build from source
- Install udev rules so you can configure the mouse without root (Linux)
- Set up auto-start on system boot and run the mapper in the background

### macOS permissions

On first install, allow **Chimera Mapper** in both:

- **System Settings → Privacy & Security → Accessibility** (to post mouse events)
- **System Settings → Privacy & Security → Input Monitoring** (to read the mouse HID reports)

The background service runs a signed app wrapper (`~/Applications/Chimera Mapper.app`) rather than the bare Cargo binary, so macOS keeps these permissions across upgrades. If you previously granted the raw `chimera-mapper` executable, remove that entry and grant the **Chimera Mapper** app instead.

To watch the native events in the foreground:

```bash
launchctl bootout "gui/$(id -u)/com.sketu.chimera-mapper"
CHIMERA_MAPPER_LOG_EVENTS=1 ~/Applications/Chimera\ Mapper.app/Contents/MacOS/chimera-mapper run
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/com.sketu.chimera-mapper.plist   # restore auto-start
```

## Usage

```bash
# List all connected HID devices
chimera-mapper list

# Run the mapper (daemon mode)
chimera-mapper run

# Dump raw HID reports (debugging)
chimera-mapper dump

# Show help
chimera-mapper --help
```

## Configure the mouse

These commands talk to the mouse's own firmware. Changes are saved to the
mouse (it reconnects for about a second after each save) and persist across
power cycles and computers.

```bash
chimera-mapper info                          # show everything
chimera-mapper battery                       # battery level, e.g. "79% (charging)"
chimera-mapper dpi 400 800 1600 3200 6400 10000   # the six DPI stages
chimera-mapper dpi --stage 2 1200            # change one stage
chimera-mapper dpi --active 3                # switch stage now (instant on the cable; a quick save over 2.4G)
chimera-mapper rate 1000                     # polling rate: 125, 250, 500, 1000
chimera-mapper led lightshow                 # off/rainbow, neon, breathing, flash, lightshow, ambilight
                                             # (see the note on the lighting switch below)
chimera-mapper --dry-run led rainbow         # print the frames instead of sending them (no mouse needed)
```

### On-board button mapping

Buttons: `left`, `right`, `middle`, `back`, `forward`, `dpi`.

```bash
chimera-mapper bind                          # show current bindings
chimera-mapper bind back alt+left            # browser back, generated by the mouse itself
chimera-mapper bind forward alt+right
chimera-mapper bind dpi play_pause
chimera-mapper bind middle disabled
chimera-mapper bind --reset                  # factory layout
```

Actions: key combos (`ctrl+shift+t`), mouse buttons (`mouse_back`, …), media
keys (`play_pause`, `next_track`, `prev_track`, `stop`, `volume_up`,
`volume_down`, `mute`, `media_player`), `dpi_up`, `dpi_down`, `dpi_cycle`,
`macro:N` and `disabled`. At least one button must stay `mouse_left`.

Binding the side buttons to key combos on the mouse makes them work on Linux
without running the mapper daemon at all.

### Macros

Up to 8 macros live on the mouse. A script is a comma-separated list of steps:
`a` taps a key, `+ctrl` holds it, `-ctrl` releases it, `50ms` waits.

```bash
chimera-mapper macro set 0 "+ctrl, c, -ctrl, 50ms, +ctrl, v, -ctrl"
chimera-mapper macro set 1 "g, g, enter" --repeat 3        # run 3 times per click
chimera-mapper macro set 2 "space, 100ms" --mode hold      # repeat while held
chimera-mapper macro set 3 "e, 500ms" --mode toggle        # click to start, click again to stop
chimera-mapper bind forward macro:0
chimera-mapper macro list
chimera-mapper macro remove 3
```

Rules the mouse imposes: up to 71 steps per macro; delays are 10–1270 ms in
steps of 10 ms, or longer in steps of 100 ms; a macro can't start with a
delay; every `+key` needs a matching `-key`.

### Profiles

```bash
chimera-mapper profile save gaming.json      # snapshot everything
chimera-mapper profile load gaming.json      # apply it in one save
```

**Lighting switch:** the mouse's three-position switch (plain light / RGB / off)
overrides software. With it on RGB, only `lightshow` and `rainbow` (mode 0)
visibly play; the other effects leave the strip dark.

Everything works over the cable and the 2.4G dongle. Over Bluetooth only
`info`/`battery` work (the mouse exposes no settings channel there), but
settings saved over the cable or dongle stay on the mouse and apply on
Bluetooth too, and the side buttons work natively. Over 2.4G, settings the
mouse reports back (battery, polling rate, …) refresh once the mouse is
moved, and button/macro uploads take a few seconds.

The mouse can't report its button table or macros back, so `bind` and
`macro list` show what chimera-mapper last wrote (kept in the config file).
The protocol is documented in [PROTOCOL.md](PROTOCOL.md).

## Custom Key Mapping

By default, the side buttons are mapped to standard browser forward (`mouse_forward` / `btn_extra`) and backward (`mouse_back` / `btn_side`) actions. You can configure custom keyboard shortcuts or mouse events to be triggered instead.

### 1. Via Command Line Arguments

You can pass `--side-action` and `--extra-action` flags when running the mapper. Flags override the saved configuration:

```bash
# Map side button to Ctrl+Shift+T, and extra button to Alt+Tab
chimera-mapper run --side-action "ctrl+shift+t" --extra-action "alt+tab"
```

### 2. Via Configuration File

Alternatively, you can save custom mapping actions in your config file (`~/.config/chimera-mapper/config.json` on Linux, `~/Library/Application Support/chimera-mapper/config.json` on macOS). The mapper fills in the `profile` section itself on first run:

```json
{
  "profile": {
    "path": "/dev/hidraw1",
    "vid": 9354,
    "pid": 23370,
    "usage_page": 1,
    "usage": 2,
    "interface_number": 0,
    "mapping": {
      "button_byte": 1,
      "side_mask": 16,
      "extra_mask": 8,
      "side_action": "ctrl+shift+t",
      "extra_action": "mouse_back"
    }
  }
}
```

### Supported Format

An action can be:
- **A key combination**: One or more modifiers (`ctrl`, `shift`, `alt`/`option`, `meta`/`super`/`command`/`win`) separated by `+`, followed by a base key. Example: `"ctrl+alt+delete"`, `"shift+space"`, `"f5"`, `"esc"`, `"a"`.
- **A mouse button override**:
  - `mouse_left` / `btn_left`
  - `mouse_right` / `btn_right`
  - `mouse_middle` / `btn_middle`
  - `mouse_back` / `btn_side` / `back`
  - `mouse_forward` / `btn_extra` / `forward`

## How it works

`chimera-mapper` runs as a small HID event translation layer:

1. **Device selection** – Uses saved profile when available, otherwise auto-detects a Kreo Chimera V1 HID interface (and prefers the cable when it's plugged in)
2. **Report reading** – Reads the mouse's button reports from the selected interface
3. **Button-state parsing** – Inspects configured report byte + bit masks for side-button states
4. **Transition detection** – Tracks previous/current state to detect only press/release transitions
5. **Action emission** – Emits mapped actions for `Forward` and `Back`
6. **Recovery loop** – On disconnect, retries until device is available again and resumes with clean state handling after reconnect

Over Bluetooth the mouse reports back/forward as normal buttons, so with the
default actions the mapper just idles there until the cable or dongle is used.
It sleeps when nothing happens: about 4 MB of memory and a couple of wakeups
per second.

## Status

Ready for daily use on Linux with the Kreo Chimera V1 over the cable, the 2.4G
dongle and Bluetooth.

Current development/testing device: **Kreo Chimera V1**

Other brands/models are **not tested yet**, so compatibility is **not confirmed**.

> [!NOTE]
> The side-button mapper was verified on Apple silicon (macOS 27.0) with the 2.4G dongle (`0x248a:0x5b4a`) by a contributor. On-device configuration (`dpi`, `bind`, `macro`, …) has only been tested on Linux so far.
